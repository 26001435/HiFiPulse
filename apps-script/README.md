# Deploy the HiFiPulse sheet receiver

`Code.gs` is the **source to paste into the existing Google Apps Script bound to your Sheet**. Committing this file does not update a deployed web app or its published CSV. Do not share Sheet edit links, private rows or Script Properties when diagnosing it.

1. **Back up the spreadsheet first.** Confirm the first tab is the same tab your `sheetCsvUrl` publishes. This receiver deliberately uses the first tab, like the previously supplied script.
2. Open the spreadsheet’s bound Apps Script editor. Replace the receiver code with `Code.gs`; keep `SCHEMA_VERSION` at **2**, which matches `config.js`. Do not edit `config.js` just to add columns.
3. Run `setup()` in the editor with the sheet owner’s authorization. On an existing sheet whose first 16 headers exactly match the old schema, it **only appends** `Provider`, `Test Status`, and `Test Profile` after `TestId`. Existing rows and their values stay in place, with their new columns blank. If the sheet has different headers or unexpected extra columns, it stops rather than risking misaligned data; inspect a backup and migrate manually. Confirm the Script Property `SUBMIT_TOKEN` matches `submitToken` in `config.js`. If the existing property is already set, `setup()` leaves it unchanged. If it was absent, `setup()` generates a new value: retrieve it privately with `showToken()` and update the static `submitToken` before testing (or configure the matching property in the Script Properties UI). Do **not** post the value in chat, issues or logs shared with others. The token is visible to users of a static site and is not strong authentication.
4. Go to **Deploy → Manage deployments → Edit → New version → Deploy** so your existing `/exec` deployment actually runs the new code. Confirm the intended access setting and privacy policy for a public pilot; a private deployment will not accept tests from other students. A saved editor file alone does not update `/exec`.
5. Run one **new real Campus Wi-Fi test** with browser GPS permission within the supported UM focus area. Check its *new* sheet row: `Provider` must say `Campus Wi-Fi`, `Test Status` should say `complete`, and `Latitude`/`Longitude` should retain **three decimal places when present** (trailing zeroes may be hidden by Sheets formatting). Old rows rounded to two decimals cannot regain precision.
6. Ensure the **same tab** is published to web as CSV and open that public CSV in a signed-out browser. Its header must contain `Provider`, and the new test’s row must include the provider, timestamp, download and approximate location. The read-only CSV is what another browser fetches; the spreadsheet’s edit URL is **not** the CSV URL. Publication can lag. On the other device, open Rankings, choose **All time** and press **Refresh**. The “Why do other devices show zero?” panel reports how many CSV rows qualify.

**Do not bulk-label existing rows Campus Wi-Fi.** The old receiver never saved the selected provider; `Connection` values like `4g` are not network identity. Only independently verified old rows should ever be corrected. Rows without GPS or outside the UM bounds also cannot qualify. `insertTestRow()` is an optional pipeline smoke test but intentionally uses an example GPS point **outside** the ranking area; delete its labelled row afterwards and use a real opt-in test to confirm rankings.

For incomplete attempts, `Test Status = incomplete` may be saved without a download speed when browser GPS is present; it remains **excluded from speed rankings**. Remote assessment evidence also needs published `Upload`, `Ping`, `Jitter` and `Accuracy` fields. Publish only after reviewing consent, location precision, access permissions, moderation and retention: public CSV is readable by anyone with its URL. A front-end-only change cannot repair a stale or inaccessible external Sheet.
